# UI Contribution Rules

هذه القواعد إلزامية قبل إنشاء أي component أو شاشة جديدة في هذا المشروع:

> قبل إنشاء أي component أو شاشة جديدة بهذا المشروع:
>
> 1. راجع `src/styles/_tokens.scss` - أي قيمة تصميم (لون، مسافة، خط) يجب أن تأتي من هنا.
> 2. راجع `src/app/shared/components/` - إذا كان يوجد مكون جاهز (زر، حقل، جدول، نافذة) يُمنع إعادة بنائه، يجب استخدام الموجود.
> 3. راجع `DESIGN_GUIDELINES.md` - لقواعد النصوص والحالات الفارغة والأخطاء.
> 4. أي مكون جديد يُبنى لأول مرة، يجب إضافته لـ `shared/components` إذا كان قابلاً لإعادة الاستخدام بأكثر من شاشة، وليس تكراره محلياً.

## إلزام التنفيذ

عند طلب إنشاء شاشة أو component جديد:

1. يجب مراجعة `src/styles/_tokens.scss` أولاً.
2. يجب مراجعة مكونات `src/app/shared/components/` قبل بناء أي عنصر واجهة.
3. يجب مراجعة `DESIGN_GUIDELINES.md` قبل كتابة النصوص أو حالات التحميل والفراغ والخطأ.
4. يجب استخدام المكونات المشتركة الموجودة وعدم إعادة بناء مكون مكافئ محلياً.
5. يجب وضع أي مكون قابل لإعادة الاستخدام عبر أكثر من شاشة داخل `shared/components`.
6. يجب استخدام design tokens بدلاً من قيم الألوان أو المسافات أو الخطوط المباشرة.
7. يُمنع منعًا باتًا استخدام `window.confirm()` أو `confirm()` في أي شاشة أو component. يجب استخدام `ConfirmDialogService` و`ui-confirm-dialog` مع تحديد `danger` أو `warning` أو `default` حسب نوع العملية.

هذه القواعد جزء من معايير المشروع، ويجب تطبيقها تلقائياً في كل عمل UI لاحق.
